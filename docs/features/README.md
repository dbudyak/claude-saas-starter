# Feature Specifications

One file per feature domain. Each file contains user stories for that domain.

## File naming

`feature-<domain>.md` — e.g. `feature-auth.md`, `feature-billing.md`, `feature-onboarding.md`

## User story format

```markdown
## US-001: [Title]

**As a** [user type]
**I want to** [action]
**So that** [benefit]

### Acceptance Criteria
- [ ] Criterion 1
- [ ] Criterion 2

### Notes
- Technical consideration or edge case

### Priority
P0 / P1 / P2
```

## Status tracking

Use `docs/TODO.md` for sprint-level tracking. Feature files are the detail behind each story.
